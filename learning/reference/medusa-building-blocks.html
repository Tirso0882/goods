Medusa building blocks

The parts of a Medusa app, which layer owns what, and how they connect. Grows with each lesson.

Layers

  1. API routesrc/api/**/route.ts: HTTP entry point
  2. Workflowsrc/workflows/*.ts: business logic across modules, with rollback
  3. Modulesrc/modules/<name>: one domain, its tables, its service
  4. PostgreSQLthe database

Each layer calls only the one below it. Architecture

API route

// src/api/admin/brands/route.ts   handles  POST /admin/brands
import { MedusaRequest, MedusaResponse } from "@medusajs/framework/http"

export const POST = async (
  req: MedusaRequest<BodyType>,   // generic: shape of the body (compile time only)
  res: MedusaResponse
) => {
  const { result } = await someWorkflow(req.scope)   // req.scope: the Medusa container
    .run({ input: req.validatedBody })               // body after Zod validation
  res.json({ brand: result })
}
  • The URL is the file's path under src/api. The HTTP method is the exported name. API Routes
  • Validation: a Zod schema in validators.ts, attached with validateAndTransformBody in src/api/middlewares.ts. Validation
  • Routes under /admin need an authenticated admin user.

Workflow

// src/workflows/create-guide.ts
import { createStep, createWorkflow, StepResponse, WorkflowResponse }
  from "@medusajs/framework/workflows-sdk"

const createGuideStep = createStep(
  "create-guide",                                    // unique step name
  async (input, { container }) => {                  // runs per request
    const guide = await container.resolve("guide").createGuides(input)
    return new StepResponse(guide, guide.id)         // (output, data for the undo)
  },
  async (guideId, { container }) => {                // compensation: the undo
    await container.resolve("guide").deleteGuides(guideId)
  }
)

export const createGuideWorkflow = createWorkflow(
  "create-guide",
  (input) => {                                       // runs once, to record steps
    const guide = createGuideStep(input.guide)
    return new WorkflowResponse(guide)
  }
)

// call it from a route, subscriber, or job:
const { result } = await createGuideWorkflow(req.scope).run({ input })
  • When a step fails, the compensations of all finished steps run, newest first. Then .run() throws. Compensation Function
  • Put steps that can't be undone (a refund, an email) last.
  • Throw new MedusaError(MedusaError.Types.NOT_ALLOWED, "...") from @medusajs/framework/utils to fail with a 400. INVALID_DATA is also a 400; NOT_FOUND is a 404.

Events and subscribers

// in a workflow: emitted only if the whole workflow succeeds
import { emitEventStep } from "@medusajs/medusa/core-flows"
emitEventStep({ eventName: "guide.created", data: { id: guide.id } })

// src/subscribers/guide-created.ts
import type { SubscriberArgs, SubscriberConfig } from "@medusajs/framework"

export default async function handler({
  event: { data },
  container,
}: SubscriberArgs<{ id: string }>) {
  const guide = await container.resolve("guide").retrieveGuide(data.id)
}

export const config: SubscriberConfig = { event: "guide.created" }   // or an array
  • Subscribers run outside the original flow. If they throw, nothing is rolled back. Events and Subscribers
  • Test: if this fails, should the main change be undone? Yes: make it a workflow step. No: make it a subscriber.
  • Send only IDs in the payload; fetch fresh data in the subscriber. To change data, run a workflow from the subscriber.
  • The Local Event Bus is for development. Production uses the Redis Event Module.

Scheduled job

// src/jobs/count-guides.ts
import type { MedusaContainer } from "@medusajs/framework/types"

export default async function countGuidesJob(container: MedusaContainer) {
  const [, count] = await container.resolve("guide").listAndCountGuides()
}

export const config = { name: "count-guides", schedule: "0 0 * * *" }
CronMeans
* * * * *Every minute
*/15 * * * *Every 15 minutes
0 * * * *Every hour, on the hour
0 0 * * *Every day at midnight
0 9 * * 1Mondays at 09:00
  • Fields: minute, hour, day of month, month, day of week. crontab.guru
  • Jobs that change data should run a workflow. Jobs run only while Medusa runs.
  • To disable, move the file out of src/jobs; don't remove the config export. Scheduled Jobs
